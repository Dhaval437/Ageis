## 1. What AEGIS is

A Windows desktop app that lets an AI agent **actually operate the user's PC** — see the screen, click, type, manage files, run commands, drive a browser — to complete tasks the user describes in plain language. The user watches every step live, takes over instantly by touching their own mouse or keyboard, and can hard-stop with a global hotkey. The user brings their own model API keys and chooses which model does what.

**One-line positioning:** *the computer-use agent you can actually trust with your machine.*

**What makes it different from a demo:** the safety layer. Anyone can wire a vision model to PyAutoGUI. Almost nobody ships scope enforcement, a hash-chained audit log, real undo, sub-100 ms human preemption, and a kill switch that works when the engine is hung. **That layer is the product.** When you are deciding what to build next and it isn't obvious, build the safety thing.

## 3. Invariants — never break these, never "temporarily" break these

1. **The human always wins.** Any real physical input pauses the agent within 100 ms. The agent never fights for the cursor, never re-takes focus while paused, never auto-resumes.
2. **The kill switch works when everything else doesn't.** It lives in the Electron main process, not the Python core, so a hung core cannot disable it.
3. **No held key survives a stop.** Every abort path releases Ctrl/Alt/Shift/Win. A stuck modifier key is a P0 bug, always.
4. **`DANGEROUS` never runs unattended.** There is no setting, no autonomy level, no "expert mode" that changes this. It is a product commitment.
5. **The FORBIDDEN list is compiled in and unreachable from the UI.** System directories, credential stores, browser cookie/login databases, `.ssh`/`.aws`/`.gnupg`, wallet files, Defender/firewall/UAC, the audit log itself, Aegis' own install directory.
6. **Approval timeouts deny.** Walking away never authorises anything.
7. **The agent never types the user's credentials.** It stops and asks the human to log in. There is no password-storage feature and there never will be.
8. **Screenshots are redacted before they leave the process.** Password fields are black-boxed in the image bytes, not just hidden in the UI.
9. **Keys live in Windows Credential Manager (DPAPI).** Never in argv, env vars passed to children, logs, error payloads, or the renderer.
10. **Nothing leaves the machine except calls to the model provider the user chose.** There is no Aegis backend, no telemetry by default, and an egress allowlist enforces it.
11. **Journal before you act.** The undo record is written before the mutating operation runs.
12. **Delete is never delete.** It is a move to the shadow store.
13. **One action per model turn, and every action is verified.** No batching. Unverified ≠ successful.
14. **The core never outlives the UI.** A headless process with mouse control and no window is the failure mode we refuse to ship.
15. **The UI is a pure function of the event stream.** No polling for task state.

## 4. Locked decisions (change only with a new Decision Log entry)

- Windows-only for v1. No macOS, no Linux, no exceptions until v1 ships to real users.
- Electron + React + TypeScript for the shell; Python 3.11 for the agent core; three processes, always.
- We own the agent loop. No LangChain, no CrewAI, no agent framework.
- UIAutomation tree first, vision second, raw coordinates last.
- Own `SendInput` ctypes wrapper, not PyAutoGUI.
- Three model **roles** (Planner / Grounder / Utility), each independently mapped by the user to any provider.
- Five of seven providers are OpenAI-compatible — one adapter with different base URLs, not seven clients.
- Bring-your-own-key. We never resell inference. Future pricing is a flat license on the app, never metered on tokens — so never couple a feature to token usage.
- PyInstaller **onedir** (not onefile) + electron-builder NSIS, per-user install, no admin.
- SQLite for everything local. No server, no cloud sync in v1.

A test redirects the global keyring and asserts the vault ignores it, and another writes and reads through the machine's real Credential Manager | `keyring.set_password()` / `keyring.get_password()` (the documented spelling, and the one whose storage location is configurable by anything on the machine) |
| 2026-09-19 | A key is refused if it contains any character below `0x20` or `0x7f`, and is capped at 1024 characters | A key is put straight into an HTTP header (`Authorization`, `x-api-key`, `x-goog-api-key`), so a CR or LF inside one is header injection into every request that adapter makes — the HTTP client refuses it too, but that is a second line, not the first, and this is the boundary where the value enters the system. The cap is Credential Manager's own 2560-byte blob limit expressed as a message a person can act on ("check you pasted the key and not a file") rather than a Win32 failure. Neither refusal quotes the key, which is tested | Validating at the adapter (too late, and seven places); trusting the provider to reject it (the injected header has already been sent) |
| 2026-09-19 | `mask_key()` shows the first 3 and last 4 characters, and **nothing at all** below 16 characters | `ARCHITECTURE.md § 5.3` fixes the display form as `sk-…abcd`, which is exactly a 3/4 split — but on a short key those seven characters are most of it, and a masked value that reveals the majority of a secret is not masked. 16 is where the hidden half wins, and every real provider key is far longer. A property test walks every length from 1 to 79 and asserts the revealed count is either zero or under half | A fixed 4/4 split with no length floor (reveals most of a short key); bullets only (a user with two keys cannot tell which is which) |
| 2026-09-19 | `storage/vault.py` imports `ProviderId` from `models/schemas.py`, accepting a storage→models import | The account name under the one Credential Manager target *is* a provider id, and typing it as `str` would let a typo create an orphan credential no screen can ever show or delete. `ProviderId` is a vocabulary — a `Literal` alias with no behaviour — so the import buys type safety at no coupling to the model layer's code. The same reasoning as `server/auth.py` importing `parent_watch.process_identity`: the concept already lives somewhere, and a third module for it would be an abstraction with one caller | A `str` account with a runtime allowlist; a shared vocabularies module for one alias |
| 2026-09-20 | The fallback chain is walked **only before the first delta reaches the consumer** | § 5.3 says fallback fires on 429/5xx/timeout, which is a rule about *when* an error is retryable — it says nothing about a stream that already produced output. Once text is in the timeline and a tool call has been emitted, a second provider starting from the top repeats both, and the Guardian would see the same call twice. So a transient failure after the first `yield` is raised, not retried; recovering from that is `P4-08`'s cancel-and-retry, which knows what the step already did | Restarting the chain at any point (duplicated timeline text and duplicated tool calls); buffering the whole answer before yielding any of it (kills streaming, which is the entire live view) |
| 2026-09-20 | The capability gate checks the **primary only**, and a fallback that cannot serve the call is dropped from the chain with a log line rather than failing it | Two different failures. A primary that cannot see is the user's settings being wrong about the job they mapped it to, and § 5.3 says refuse loudly at task start. A secondary that cannot see is only reached when the primary is down, and quietly using it would answer a vision question with nothing — while refusing the whole task would tell the user their primary is broken when it is their spare. Dropping it keeps the chain honest about what it can actually deliver | Gating every link (a blind spare bricks a working primary); gating none (a fallback silently answers a vision question with nothing) |
| 2026-09-20 | `RoleRequest` — a request with **no `model` field** — rather than a `ChatRequest` whose model the router overwrites | Each attempt in a chain genuinely runs a different model, so a request object carrying one would be wrong for every attempt but the first, and a caller would eventually believe it. The role map is the authority on which model answers; `bind(choice)` is the only place a model is named, and it is also where the user's saved params are merged under the request's own. The cost is nine duplicated field declarations, which is cheaper than a field that lies | `ChatRequest` with `model` documented as ignored; making `ChatRequest.model` optional (every adapter would then have to handle a request with no model) |
| 2026-09-20 | The router closes the adapter's generator itself, in a `finally`, rather than relying on `async for` | `async for` does **not** close the iterator it read. When the consumer abandons the router's stream — preemption, a budget breach — `GeneratorExit` is thrown at the router's `yield` and the adapter's generator is left suspended on a socket that is about to go, which is exactly the `generator didn't stop after athrow()` noise `P1-02` fixed one layer down. Each layer closes the layer below it, so the stop path stays clean however many links it has. A test abandons a router stream and asserts the provider's `finally` ran | Trusting the event loop to finalise it (the noise, on every stop); `contextlib.aclosing` (it does not type-check against the protocol's `AsyncIterator`) |
| 2026-09-20 | `ProviderUnavailableError` is a `RouterError`, **not** a `ProviderError`, and the pool re-runs `normalise_base_url` on the saved `custom` address every time it builds that adapter | A `custom` gateway with no address, or an unusable one, is a settings problem the user fixes in Models — not a provider that failed, so the chain must not treat it as a hiccup and retry around it. Re-validating at build time rather than trusting what was persisted is the same argument `P1-05` makes about the URL deciding where a key is sent: settings can be written by an older build or edited by hand. `P1-05`'s refusals never quote the address back, so the message passes straight to the user | Reusing `ProviderAuthError` (would make a missing address look like a rejected key); trusting the stored URL (the one string in a provider that decides where a key goes) |
| 2026-09-20 | Spend is a **durable table** (`usage`, `m0002_usage.py`) — a ninth table, not `tasks.cost_cents` | A per-day ceiling that an app restart clears is not a ceiling, it is a suggestion a crash loop can spend past. `tasks.cost_cents` is a per-task total with nowhere to put tokens, no way to distinguish an unknown price from zero, and no row at all for a call made outside a task (a `P1-10` *Test*). `ARCHITECTURE.md § 7` is updated rather than worked around | An in-memory total (dies with the process); summing `tasks.cost_cents` by date (cannot answer any of the three) |
| 2026-09-20 | The day a ceiling counts is the **local** date, stored as a `day` column rather than derived from `ts` | "Ten dollars a day" is a promise to a person about their day, and theirs ends at their midnight, not UTC's. Storing the date the row was counted under means the boundary cannot be re-derived differently by a later reader, and the index is on the column the query filters | UTC dates (wrong for most of the world for part of every day); deriving the date from `ts` at query time |
| 2026-09-20 | A breach is refused **at the door** — `check()` raises before a call, `record()` never raises | Every adapter emits its one `UsageDelta` at the *end* of a stream, so a cost is known only once it is spent. Aborting there throws away an answer the user has already paid for and leaves half a turn in the timeline, while stopping the *next* call costs nothing and is where § 5.3's "pause the task and ask" actually belongs. `record()` still publishes `cost.updated` with `breach` set, so the UI pauses immediately | Raising from `record()` and killing the stream mid-flight (wastes what was bought); estimating a call's cost before making it (a guess, and every provider prices differently) |
| 2026-09-20 | **Token ceilings as well as cost ceilings**, set far above any honest task (10M per task, 100M per day) | An unknown price is `None` and is never summed as zero, so on a `custom` gateway or an unlisted OpenRouter model a cents-only guard never fires at all — exactly the providers a privacy-minded user picks. The backstop is deliberately loose so a *priced* provider always meets its cents ceiling first and nobody meets the token one by accident. Proved both ways by hand: a priced model stopped on `task_cents`, an unpriced one ran until `task_tokens` with its cents total still reading 0.0 | Cents ceilings only (no guard at all on unpriced providers); treating an unknown price as some default rate (a guess, in the direction that overspends) |
| 2026-09-20 | `storage/usage.py` holds the core's **first long-lived database connection**: one connection, `cross_thread`, serialised under a lock | `P0-10` left "how connections are shared" to the first real writer, and this is it. One connection under a lock is cheaper than a pool for a table written once per model call, and `cross_thread` is needed for the same reason `EventHub.publish` is thread-safe — the agent loop and the preemption watcher are not on the event loop. `db.connect()` gained the keyword rather than a raw connection skipping the pragmas | A connection per write (re-applies four pragmas each time); a thread-local pool (bookkeeping for one writer) |
| 2026-09-20 | Money below ten cents is shown to four decimal places (`$0.0075`), not two | Found on the first live run: a spend of 0.75 cents against a limit of 0.5 cents both rendered `$0.01`, so the message said a number had reached itself. A cheap call really does cost fractions of a cent — it is why `Usage.cost_cents` is a float — so the display has to carry them | Two decimals everywhere (rounds the two sides of a breach into the same figure); showing cents with a `¢` sign (a second unit in the same sentence) |
| 2026-09-20 | The Models screen's **wire shapes are their own models in `server/schemas.py`**, converted to and from `RoleMap`/`BudgetLimits` in `models/service.py` | The internal types cannot express what the screen needs. `RoleMap` is a `Mapping` keyed by a `Literal` — no faithful TS spelling, and `typegen` would refuse it — and it **requires all three roles**, while the state the screen spends its whole first run in is *a role with no model*. `ModelSettings` therefore has three named nullable fields, which is also the better TS. One module converts, so the two type systems meet in one place | Generating TS from `models/router.py` (`§ 5.3` says that layer is internal and has no TS mirror); making `RoleMap`'s roles optional (every reader would then have to handle a half-configured map, including the agent loop) |
| 2026-09-20 | `ProviderId` is **imported into** `server/schemas.py` rather than restated | `typegen` exports every module-level `Literal` alias, imported or not, so one import gives the renderer `PROVIDER_IDS` *and* a named `ProviderId` on five interfaces instead of the same seven-way union inlined five times. It is a vocabulary with no behaviour — the same argument as `storage/vault.py` importing it (2026-09-19), and the reverse import already exists (`models/budget.py` → `EventType`) | Restating the seven ids (a hand-written mirror of a Python model, which `§ 4` forbids); leaving the field typed inline (correct, but the renderer then has no list to validate against) |
| 2026-09-20 | `BudgetLimitsSpec` **restates** `models/budget.py`'s four defaults, with a test asserting they agree | `budget.py` already imports `server/schemas.py` for `EventType`, so importing back is a cycle. Restating also fixes a real hazard: an omitted `limits` now means *the defaults* rather than *no ceilings at all*, so a settings document written by an older build cannot silently remove every ceiling the user was relying on. Same shape as `UsageRole` being held to `ModelRole` by a test | Importing the constants (import cycle); defaulting every ceiling to `None` (an older document would disable the budget guard entirely) |
| 2026-09-20 | `GET /models/catalog` **never calls a vendor** — it is this build's model tables plus whatever Ollama on loopback answers | This is the screen you open when nothing works, so it has to open on a machine with no internet, and a catalogue fetch would spend a request and leak the fact that the app started. `nvidia`/`openrouter`/`custom` — and any model newer than a pinned table — answer `free_text_model`, which is exactly what `COMPATIBLE_UNKNOWN` (`P1-05`) already exists for. The cost is that those three are typed in rather than picked | Fetching `/models` per provider at catalogue time (needs a key, a network and a timeout budget, on the one screen that must work without them) |
| 2026-09-20 | Keys get **two routes and no reader**: `PUT`/`DELETE /models/keys/{provider_id}`, added to `§ 9.1` | `§ 9.1` had `POST /models/validate` but nowhere to put a key, and the key has to enter somewhere — the user types it. So it travels one way only: `has_key` and `mask_key()`'s `sk-…abcd` are the whole vocabulary coming back, `KeyRequest.key` is `repr=False` so no model repr can leak it, and it is deliberately **unconstrained** in Pydantic because a validation error echoes the value it rejected. Every refusal comes from `KeyVault`, whose messages quote nothing. Tested by saving a key and searching every other response for it | One `POST /models/keys` taking a provider in the body (same surface, less obvious what is addressed); validating length/characters in the schema (a 422 would then carry the key) |
| 2026-09-20 | A malformed request is a **422 that repeats none of it**, app-wide | FastAPI's default handler returns the offending *input* beside each error. The only client is a renderer that displays text the agent scraped off the user's screen and is the field a key is typed into, so an echo is a route into a log, a devtools panel or a pasted bug report. The handler logs the field's *name* and answers one fixed sentence; a malformed request from the renderer is a bug in the renderer, and the location is enough to find it | Leaving FastAPI's default (echoes whatever was sent); handling it only on the key route (the next route with a secret in it would have to remember) |
| 2026-09-20 | The Models screen edits a **draft**, and `edit` takes an **updater**, not a value | Two copies is what makes *Save changes* and *Discard* possible, and what lets the screen say there is something unsaved. The updater is not style: with a value, every handler closes over the draft it was rendered with, so two edits inside one React batch lose one of them. Found by driving the built app — three role cards were given a model in one tick and only the last survived. A regression test now does the same thing in one `act` | Editing the saved settings in place (nothing to save, nothing to discard); `edit(value)` (correct for a human clicking one control at a time, wrong the moment anything batches) |
| 2026-09-21 | The core has **one coordinate space: physical pixels on the virtual desktop**, and no logical (DIP) coordinates anywhere | Under Per-Monitor awareness, UIA rectangles, `GetCursorPos`, monitor bounds and `SendInput`'s absolute range already agree in physical pixels, so a single space means no number ever needs a "which space is this?" question and no conversion can be forgotten. Measured on the dev machine (3200×2000 at 200 %): the default, **unaware** `python.exe` is told the screen is 1600×1000 while `SendInput` still spans the real panel — every click would land at half its coordinates with no error. `Monitor.scale` is kept for display only | A logical-coordinate model with per-monitor conversion (the DIP layout of a mixed-DPI desk is not a simple per-monitor scale, and every caller would have to remember to convert) |
| 2026-09-21 | `ensure_dpi_awareness()` runs **first** in `main()` and never raises; `query_layout()` is what **refuses** a thread that is not per-monitor aware | The process default can be set exactly once and the first caller wins — a library that set *system* awareness first would make the wrong choice permanent, so it runs before the token is read. A failure must not stop the core, for the vault's reason: the Models screen should still open. The refusal lives where coordinates are produced instead, and checks the **calling thread**, because awareness is per-thread in Windows and a thread can override the process. Code, not an exe manifest, so the dev venv and the packaged `aegis-core.exe` behave the same | Failing startup when awareness cannot be set; handing an unaware thread scaled coordinates; relying on a PyInstaller manifest (P7) that the dev run would not have |
| 2026-09-21 | `to_absolute()` picks the **middle** of the run of `SendInput` values that land on a pixel: `((2x+1)·65536) // (2w)` | Windows maps an absolute value back with `floor(n·w/65536)`. The common `x·65535/(w−1)` misses pixels — mutated in, it made the **live** cursor round-trip test miss real pixels on a 3200-wide screen, as well as the exhaustive axis test at every width ≥ 1920. The midpoint is exact for any axis up to 32 768 px and has half a pixel of margin against a rounding difference either way. A point in a dead zone is refused rather than left for Windows to clamp onto an edge nothing asked for | The `65535/(w−1)` formula most samples use; the edge `x·65536/w` (exact in theory, zero margin) |
| 2026-09-21 | A `DisplayLayout` is a **validated snapshot**, re-read before every action and never cached; equality and a 16-hex `fingerprint` include DPI; a read whose `SM_*VIRTUALSCREEN` is not the monitors' bounding box is **retried** (3×) | Monitors and the virtual-screen metrics are separate reads, so a hot-plug can land between them — the mismatch is the signal, and a real change settles within one retry. A query costs well under a millisecond, so caching would buy nothing and cost `RECOVERY.md § 3.3`'s "never reuse a pre-change bounding box". DPI is in the fingerprint because a scaling change leaves physical bounds alone but re-lays-out every window. `verify_layout()` is the call `P2-08` makes before a click | A `WM_DISPLAYCHANGE` listener (needs a window and message loop, and still races the click); caching the layout until a change event |
| 2026-09-21 | `perception/display.py` + `perception/win32.py` added; `actuation/` will import the layout from `perception/` | `ARCHITECTURE.md § 4` had no home for the coordinate model, and it is what perception *produces*. The ctypes declarations get their own file for the same audit reason as `actuation/win32.py`, with a **separate `WinDLL`**, because `argtypes` is set per `WinDLL` instance and sharing one would let a declaration here change a prototype the input layer relies on. `P3-01`'s absolute `move_to` will depend on `perception.display`, which is a one-way import | A shared `aegis_core/win32.py` for every binding; putting the model in `actuation/` (perception would then import actuation to describe the screen) |

## 6. Glossary — use these words exactly, in code and in UI

| Term | Means |
|---|---|

| **Step** | One perceive→plan→act→observe cycle within a task |
| **Tool** | A capability the agent can invoke (`fs.move`, `input.click`) |
| **Guardian** | The policy engine every tool call passes through |

| **MAIN** | The Electron main process |

## 7. Facts about how this project is built

- **Solo developer** (Dhaval, Windows, VS Code, GitHub Desktop, comfortable in Python/React), building this with Claude Code across many sessions. Optimise for: small commits, clear task boundaries, and documents that carry context between sessions. Avoid: heroic multi-day refactors, clever abstractions with one caller.
- **Sessions are the unit of work.** Assume the next session remembers nothing. `PROGRESS.md § 12` is the handoff.
- **Commit messages start with the task ID** (`P3-05: …`) so history maps to the tracker.
- **Start `P7-09` (antivirus false-positive submissions) in week one.** It takes weeks of calendar time and blocks launch. Everything else is code; that one is waiting.
- **The benchmark suite (`P4-12`) is the definition of "is it good".** Build it early, run it often, record cost baselines.

## 8. Things that will go wrong (forewarned)

1. **Grounding accuracy is 60% of perceived quality.** Budget real time in P2/P3; do not rush to P5 because tool code is easier to write.
2. **Prompt injection through screen content** is the newest and least-defended attack class in computer-use agents. `P8-01`/`P8-02` are not optional polish.
3. **Antivirus will flag you.** Signing + vendor submissions, started early.
4. **Vision-model cost adds up fast** — one image per step, downscaled, with a budget guard.
5. **DPI and multi-monitor bugs** are the single most common source of "it clicked the wrong place". `P2-01` deserves more care than its one line suggests.
6. **Scope creep to macOS** will feel tempting the moment Windows v1 works. Don't.
